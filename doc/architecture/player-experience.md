# 玩家体验设计 v1.14.0

> 版本：1.14.0 | 生效日期：2026-10-07 | 变更类型：**VIP剧情秒出升级为「接管预生成流」，全程一次AI请求**（对齐 `ai-architecture.md` v4.13.0）。修复 v1.13.0 遗留的浪费：旧实现下 VIP 后台用非流式整章预生成、回填 `NarrativeText`，玩家若在回填前点选会降级**新开第二个 AI 请求**，而那个后台预生成请求无句柄无法取消、继续跑完作废（章节档翻倍到 6000 字后浪费窗口更大）。现改为**流式预生成 + 可重放缓冲接管**：后台用流式为该选项预生成、逐 chunk 写入缓冲，玩家点选时**接管**这个正在进行的流——已缓冲内容立即回放（首字≈0）、追平后续读同一个流，**无论预生成跑到哪都只有一次 AI 请求**；点选同时取消未选选项的预生成以止损。对玩家的可感知变化：**开启 VIP 后点选几乎总能秒出剧情（不再依赖“等得够久”），且后台不再白烧第二个请求**。代价不变：叙事 token 约翻倍（2选项各预生成一次、只用1个，未选选项点选时即取消）。详见「快速行动选择」。

## 信息层次三层架构

### 第一层：叙事层（纯AI文字）

通过叙事自然传达的信息：

- NPC态度变化
- 环境细节
- 道德后果
- 时间暗示

### 第二层：氛围UI层（视觉非精确）

界面上可见但非精确数值的信息：

| 元素 | 呈现方式 |
|------|----------|
| HP | 百分比血条 + 四级状态词 |
| 时段 | 界面色调 + 时段标签 |
| 天数 | 倒计时显示 |

### 第三层：可查阅层（主动打开）

玩家需主动打开查看的详细信息：

- 角色面板（属性/技能/等级）
- 背包列表
- 线索笔记本
- 骰子历史记录

## 线索笔记本

### 功能定位

AI自动整理玩家已获取的线索，辅助玩家回顾信息。

### 数据来源（资产账本）

无形资产（情报/线索/号码/承诺等）由物资官（道具AI）依**书记官蓝图**记入已知情报账本（`KnownAssetService`）。记账链（书记官 → 物资官 → 推送）**与叙事流式并行**，`UpdateKnownAssets` 在玩家阅读叙事的窗口内推送——线索区通常在叙事读完前已刷新；后续轮次引用已登记情报（如“掏出那张纸条”）会被门卫读账本放行。

账本随会话生命周期清理：重开副本/放弃会话时后端清空已知情报账本，前端同步清空线索区，不残留旧周目线索。

### 设计规则

- AI自动整理，无需玩家手动记录
- 标注状态："未验证" 或 "矛盾"
- 风格像"角色自己在记笔记"（手写感、有涂改）
- **不直接告诉**下一步去哪
- 只提供线索，不提供答案

## 玩家输入引导

### 自由输入框语义（v1.9.0）

自由输入框不再作为“本轮行动”提交，而是作为“**中长期目标声明**”：

| 方面 | 行为 |
|------|------|
| 提交后 | 仅写库（`GameDungeonSession.CurrentPlayerGoal`），**不触发任何 AI**、**不刷新当前选项**、**不失效预计算缓存** |
| 反馈 | 推送一条 info 系统消息：“已记下你的想法，接下来的选项会围绕它展开”（空目标静默覆盖，不弹提示） |
| 生效时机（v1.12.1） | **下一轮点选回放**（正常游玩主路径；缓存未命中回退/危险确认时走真实推进轮）时辅导员（第七个AI）先消歧目标、评估进度、产出 `next_focus` 策略方向并落库 `CoachState`，再注入书记官 `[辅导员策略指引]` 引导 `suggested_actions`；预计算/不可行短路轮复用已落库 `next_focus`（辅导员失败则回退注入原始 `[玩家当前目标]`） |
| 生命周期 | 覆盖式存储（新输入覆盖旧目标）、**不自动清空**、跨会话持久化（断线续玩/重新开始/跨设备/页面刷新均一致） |
| 长度限制 | 前端 100 字硬上限（textarea `maxlength` + `handleInput` 双重保险，右下角显示剩余字数，≤20 字变琥珀色）；后端 200 字兼底截断 |
| 目标 chip（v1.12.0） | 输入框上方 chip 优先展示**辅导员消歧后的目标**（`clarifiedIntent`，无则回退玩家原始输入）；有子目标/进度时可展开查看 📍当前子目标 + 📊进度；× 按钮发送空串覆盖 + 本地 `currentGoal`/`coachState` 清空 |
| 达成/失效推送（v1.12.0） | 辅导员判定目标达成 → 推 success 系统消息（🎯 目标达成：{意图}（{completion_check 依据}））+ 归档清空 chip；判定失效 → 推 warning（⚠️ 目标受阻：{原因}）+ 归档清空，提示玩家重设 |
| 断线回填（v1.12.1） | `DungeonReady` / `ActiveSessionCheck` / 每轮记账后（回放轮主路径 + 真实轮回退）`UpdatePlayerGoal` 推送均带回 `CoachState`，断线续玩/刷新/跨设备恢复 chip 进度 |
| 目标冲突 | 书记官模板规定：若目标与本轮既定事实/世界状态冲突，**优先输出化解冲突或调整目标的路径**，不得违反既定事实 |
| 目标含未确认实体（v1.12.2） | 若目标涉及世界尚未确认存在的人/物/地点，选项不会直接给「寻找/接触该实体」（那会被可行性门卫判不可行、按钮置灰成死按钮），而转化为「向X打听其下落」「前往查探是否真有」等过渡行动；且探索/寻人/打听类行动本身即使一时查无对象也不再判死，由剧情演绎「查无此人/扑空」 |

### 分层响应

| 风险等级 | 处理方式 |
|----------|----------|
| 低风险 | 直接执行，叙事反馈 |
| 高风险 | 先描述场景，引导玩家细化行动 |

### 隐性质量奖励

- 有创意/策略的描述可获得：优势判定 / DC减免
- 只奖励"聪明细节"：
  - 利用环境特征
  - 预见潜在风险
  - 运用角色技能优势
- **不奖励**纯粹堆砌描写
- **不明确告知**此机制存在

### 输入兼容性

- 命令式输入（"我搜索房间"）→ 正常执行
- 描述式输入（"我小心翼翼地翻开地毯角落"）→ 可能触发奖励
- 两种方式均可正常游玩

## 防卡关提示

### 被动暗示

- 触发条件：连续 2-3 次无效行动
- 方式：AI通过叙事暗示方向（环境细节/NPC提示）
- 不直接告诉答案

### 线索笔记本回顾

- 引导玩家回顾已收集线索
- 通过线索关联暗示方向

### 设计约束

- **不设**主动"求助按钮"
- 保持沉浸感优先

## 玩家反悔机制

### 核心原则

**铁人模式**：无存档 / 无回溯

### 安全机制

| 场景 | 处理 |
|------|------|
| 高风险/不可逆行动 | 确认步骤（"你确定要……？"） |
| 日常行动 | 不需确认，直接执行 |
| 误操作 | 短暂编辑窗口（发送后数秒内可修改） |

### 设计目的

- 让每个决策都有重量
- 防止误操作但不打断节奏

## 快速行动选择（预计算缓存）

### 功能定位

降低玩家行动等待时间。每次行动推演结束后，**书记官AI**（v4.0.0 前为导演AI）在记账时一并输出2个建议行动选项，后台并行预计算到**导演层**（L1，v4.1.0）。预计算就绪快（~15s），下一轮选项通常在玩家读完本轮叙事时即已备好；玩家点选后骰子/状态秒级推送、叙事实时流式生成，无需等待全链路推演（~15-25秒）。**v1.7.0 起选项覆盖全场景**：除常规轮外，纯叙事轮、首次进入/重新开始/同题异卷重玩的开场轮、不可行短路均通过书记官 SuggestionsOnly 轻量模式产出2个选项（详见降级表与 `ai-architecture.md` v4.2.0「全场景行动选项覆盖」）。

**VIP模式（v1.14.0，剧情秒出·全程一次AI请求）**：`StatusPanel` 下拉菜单 ⚡ 开关（会话级、不持久化）。开启后预计算拆两阶段：**导演层就绪（~15s）即放开按钮点击**（与非 VIP 一致，不再等叙事），叙事正文改由**后台流式预生成**、逐 chunk 写入可重放缓冲。玩家点选时**接管**这个正在进行的流——已缓冲内容立即回放（首字延迟≈0）、追平后续读同一个流直到完成，**无论预生成跑到哪都只有一次 AI 请求**（不再像 v1.13.0 那样“回填前点选就降级新开第二个请求、旧请求白烧”）；点选同时取消未选选项的预生成止损。仅当该选项预生成失败（缓冲 faulted）才降级实时流式（等同非 VIP、不卡）。代价：叙事 token 约翻倍（2个选项各预生成一次、玩家只用1个）。

### 交互流程

1. 前台导演返回即开始叙事流式推送；记账链（书记官 → 物资官 → 背包/情报推送）在叙事播放期间完成，随后预计算启动（读本轮最新账本，只算到导演层）
2. 叙事流式输出完成后，叙事区和输入区间出现2个行动选项按钮
3. 预计算进行中时按钮显示“预计算中...”加载指示器（禁用）；因 L1 就绪快（~15s），典型情况下预计算在玩家阅读期间已完成，按钮直接可点
4. **点击选项** → 缓存命中：骰子结果 + 游戏状态秒级推送；叙事默认**实时流式生成**（非回放缓存正文），**VIP模式则接管后台流式预生成缓冲（回放已缓冲 + 续读同一流，全程一次请求，秒出，v1.14.0）；仅该选项预生成失败才降级实时流式**；与此同时后台并行 await 书记官回填 → 落库记账 → 启动下一轮预计算
5. **输入自定义文本**（v1.9.0）→ 视为**目标声明**，仅写库 + 推送 info 反馈；当前选项列表**保持不变**，玩家仍需从中选一个；下一轮书记官产出的选项会围绕该目标生成（详见「玩家输入引导 · 自由输入框语义」）

### 选项设计原则

- 书记官AI每次输出**恰好2个**行动建议
- 两个选项方向应有**差异性**（如“社交互动” vs “潜行探索”）
- 行动文本简洁（15字内），为玩家视角
- 选项与当前叙事自然衍接，是本轮推演结果的合理延伸

### 降级策略

| 场景 | 处理 |
|------|------|
| 预计算失败 | 按钮保持禁用，玩家可手动输入走常规流程 |
| 缓存过期（1天） | 以所点选项文本作为玩家输入走常规全链路（等同手动输入） |
| 缓存未命中 | 同上，保留成人模式开关状态；选项文本不可得（旧客户端）时提示玩家重新输入 |
| 背包超载（≥100%） | 点击选项同样在入口被阻断（与手动输入一致） |
| 书记官未输出2个选项 | 不启动预计算，不显示按钮 |
| 纯叙事轮（查看背包/原地观察等无状态变化的行动） | 与常规轮无差别：走完整导演→书记官链路产出2个选项（v1.7.1：分类AI已不再区分是否需要状态变更，此前「走轻量模式」「跳过书记官」均已废弃） |
| 开场轮（首次进入/重新开始/同题异卷重玩） | 开场叙事推送后即以 SuggestionsOnly 产出2个引导选项（新手引导），持久化 + 预计算 + 推送，与常规轮一致 |
| 不可行短路（`infeasible`） | 推送拒绝叙事 + 以 SuggestionsOnly 产出2个「补救方向」选项（v1.7.0 修复此前短路无反馈的缺陷） |
| 挂起/断线恢复 | 续上离开前最后一轮：跳过回归旁白，以 DB 持久化的选项文本推送（不重跑预计算，省 token）；点选后缓存命中秒响应、未命中走全链路 |
| 成人轮（成人模式开启 / 分类判定成人） | 与常规轮**完全一致**：走完整导演→叙事→书记官，书记官产出2个选项，**同样做预计算**（v1.10.0：预计算继承会话级成人模式，用成人模型预掷），点选秒响应。切换成人模式后当前缓存选项按旧模式回放（最多一轮过渡），下一次预计算起切换 |
| VIP模式该选项预生成失败（缓冲 faulted，v1.14.0） | 自动降级实时流式生成叙事（与非VIP一致），玩家不卡住；仅损失“秒出”体验。注：VIP 按钮可点时刻与非VIP一致（~15s）；点选时接管正在进行的预生成流（全程一次请求），不再有“回填前点选就新开第二个请求”的浪费 |
| 副本结束态（完成/放弃/死亡） | 刻意无选项（设计接受） |

## 玩家操作方式

### 输入形式

- **选项点击为主**（v1.9.0）：书记官每轮产出 2 个建议行动选项，玩家点选后走完整链路
- **自由输入框 = 目标声明通道**（v1.9.0）：表达中长期意图，仅写库，不触发 AI；下一轮书记官产出的选项会围绕该目标生成
- AI 自适应解析玩家意图

### AI响应策略

- 模糊输入：AI请求澄清或按最合理理解执行
- 违反规则的输入：叙事化拒绝（不直接说"不允许"）
- 超出能力范围：通过叙事暗示限制
